## 1 bis. Strates

Rôle : donner la légende avant de s'en servir. Placée entre la barre d'identité et les travaux, elle définit les trois étiquettes qu'on retrouve ensuite sur chaque cas.

- Titre de section : Strates
- Introduction : Chaque surface montre le même objet, tenu par les règles du design system, défini une seule fois dans le modèle. Seul l'usage change, selon qui le manipule, humain ou agent.

| Strate | Définition | Exemples |
| --- | --- | --- |
| Surfaces | Les endroits où l'on rencontre le produit. Je ne conçois pas un écran, mais la présence d'un même objet sur chacun d'eux. | web · mobile · Outlook · CLI · API · agents |
| Design system | Les règles qui traduisent le modèle en surfaces : quoi utiliser, et surtout quand. Écrites pour les équipes, et de plus en plus pour les agents. | tokens · composants · patterns · règles d'usage |
| Modèle | L'architecture interne du produit : ses objets, leurs relations et leurs dépendances, leurs états, et qui a le droit d'agir sur quoi. Ce qui reste quand on retire les écrans. | objets · relations · dépendances · états · droits |

## Révision du 13 octobre (historique)

Principe appliqué le 13 octobre : la thèse est affirmée une seule fois, dans l'accroche ; le reste de la page montre, décrit et nuance. Chaque texte est passé au test : est-ce une évidence pour un senior, une affirmation sans preuve sur la page, ou une phrase qui exclut un poste visé ?

| Endroit | Avant | Après | Raison |
| --- | --- | --- | --- |
| Accroche | inchangée | inchangée | La seule thèse de la page |
| Sous-titre | inchangé | Faute corrigée (écosystèmes) | Factuel, déjà juste |
| Titre des cas | Trois systèmes rendus lisibles | Trois produits, trois problèmes de structure | Répétait l'accroche et jugeait son propre travail |
| Intro des cas | Chaque cas part du modèle, pas des écrans… | Pour chaque cas : ce qui ne tenait plus, ce que j'ai structuré, ce que ça a coûté, et ce qui est devenu réutilisable | Troisième « modèle contre écrans » de la page ; la description annonce aussi la section 4 bis |
| Titre de la méthode | Concevoir l'architecture produit comme un système | Comment je travaille | Une position consensuelle n'apporte rien ; un titre descriptif laisse le contenu travailler |
| Nuance de la méthode | absente | Trois gestes, rarement dans cet ordre strict ; parfois le prototype d'abord | Dire quand la méthode ne s'applique pas est un signal de séniorité |
| Modéliser | …avant la première maquette | …et le vocabulaire que toute l'équipe partage | « Avant la maquette » est une évidence ; le vocabulaire commun est un bénéfice concret |
| Systématiser | …un modèle d'usage, lisible par une équipe comme par un agent | …qui disent quand et comment utiliser chaque élément, pas seulement à quoi il ressemble | Le point de vue se démontre dans les cas et sur la page Système, pas sur la landing |
| Direction | Le design ne disparaît pas, il se déplace… c'est désormais le rôle du design system | Section supprimée : c'était la méthode appliquée à un autre contexte, sans preuve propre. La recherche de poste passe dans le contact, les supports dans les cartouches des cas | Aucun cas ne prouve encore l'expertise agents ; une direction assumée est crédible, une expertise affirmée ne l'est pas |
| Contact | Vous construisez un produit technique difficile à rendre lisible ? Parlons-en. | Un poste, un produit, une question ? Écrivez-moi. | Troisième « lisible », ton commercial ; le nouveau s'adresse aussi aux recruteurs |
| Verbes de la méthode | Comprendre / Modéliser / Livrer | Cadrer / Modéliser / Systématiser | Comprendre et livrer décrivent tout designer ; l'axe discovery → delivery et la recherche sont portés par les étiquettes de temps et les pratiques |
| Points de vue | Page Système et sections 4 bis des cas | Cinq écrits dans un onglet dédié ; la page Système devient l'écrit 04 et son annexe | Une thèse se défend dans un article ; sur la landing, elle passe pour une affirmation |

Ce qui reste affirmé ailleurs, volontairement : les points de vue, dans les cinq écrits, où chacun est argumenté et relié aux cas.
